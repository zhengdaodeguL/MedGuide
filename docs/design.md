# MedGuide 设计规范

## 设计方向

**医疗信息工作台**：面向有健康疑问、需要整理症状和准备就医的普通用户。界面以清楚的信息层级、可读的中文正文和可追溯的资料为主，让用户能够判断已知情况、风险提示和下一步需要补充的信息。

采用浅纸白、墨黑与医疗蓝绿色，配合细边线和有限的圆角。参考 21st.dev 公开组件展示中的布局、间距和状态表达，不直接复制模板，不引入第二套组件库。继续使用 React、原生 CSS 和 `lucide-react`，根据本项目的咨询流程组织组件。

页面文案直接说明用途和操作。避免抒情标题、重复的品牌口号、装饰性英文标语，以及暗示诊断能力或服务正常的无依据表述。主界面不挂载风景背景、摄影、光效或风景控制器。

## 色彩与排版

基础令牌统一放在 `frontend/src/styles.css` 的 `:root`，组件引用令牌，避免另建一套局部配色。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#f3f5f7` | 浅纸白页面背景 |
| `--surface` | `#ffffff` | 主咨询区、表单和内容表面 |
| `--ink-950` | `#14202b` | 标题与主要文字 |
| `--teal-700` | `#147886` | 主操作、链接与当前状态 |
| `--line` | `#dbe2e9` | 内容分组、表单和面板细边线 |

次级文字使用足够清楚的中性灰，不以降低对比度代替视觉层级。关注和高风险状态保留独立的警示色，同时显示文字和图标，不仅依靠颜色区分。

正文默认 14px，辅助文字保持 11–12px；手机消息正文不小于 14px。输入控件在手机上使用 16px 文字，避免浏览器聚焦时缩放。标题随视口调整，不能挤压正文、表单或主要操作。字体使用本机系统字体栈，不依赖第三方字体请求。

长消息、症状、来源名称和结构化结果允许换行。风险提示、错误原因和下一步问题不得通过省略号隐藏。装饰性间距不能造成大面积无内容区域，也不能以缩小字体塞入更多内容。

## 布局与组件

### 登录与注册

桌面登录页采用左侧用途说明、右侧账户表单。用途说明提供简短的任务入口介绍；账户表单清楚区分登录、注册、校验错误、连接异常和提交状态。手机切为单列，保留产品用途与表单，隐藏重复的示例介绍。

用户名、密码、密码确认、可见性切换和隐私提示沿用既有认证契约。表单状态不能暴露账户之外的健康信息，密码不做自动修剪或格式改写。

### 咨询工作台

桌面由左侧会话栏、中间咨询区、右侧信息面板构成：

- 左侧呈现当前会话、新建入口和简短使用提示，不展示不存在的历史记录。
- 中间以提问和回答为主。首页提供身体不适、用药疑问、检查解读、就医准备四类可编辑模板；选择模板只填写草稿，不自动发送，也不假设年龄、病史或症状。
- 右侧依次组织风险筛查、已提供的信息、处理进度和参考资料。结构化查询结果只在接口实际返回时展示。

主咨询区尽量使用平整表面；卡片和输入区采用 8–12px 圆角、1px 细边线和克制的阴影。引用列表通过分隔线和排版区分条目，避免层层套卡片。图标用于识别操作或状态，不作持续摆动的装饰。

1020px 以下主咨询区切为单列，左右栏通过抽屉打开；抽屉保留焦点循环、Escape 关闭、背景 `inert` 和触发器焦点恢复。窄屏与短屏都必须能滚动到表单、最后一条消息和输入区，不能出现水平溢出或被固定元素遮挡。

## 状态与处理进度

节点进度按节点标识和 `status` 聚合，不依赖事件数量或固定执行路径。界面必须区分已完成、按条件跳过、处理中与尚未开始；`skipped` 不能显示为已执行。最终 JSON 响应、SSE 最终响应和断流后的幂等恢复使用相同事件状态，不能在答案已返回后仍显示全部待处理。

风险未评估时明确显示未评估；风险状态同时用文字、图标和颜色表示。高风险优先显示紧急就医指引，不提示用户继续等待普通资料检索。空引用、资料服务不可用和查询被安全规则阻止是不同状态，应根据接口实际结果说明。

所有操作保留 hover、focus、active、disabled 状态。键盘焦点清楚可见，图标按钮提供可读名称；手机主要触控目标保持足够间距，避免误触。错误消息应给出可操作的重试或修正方式，并保留用户草稿。

## 动态与资源

不挂载 `ScenicBackdrop` 或 `SceneryControls`，不为已移除的装饰背景读写偏好、加载摄影或运行媒体状态监听。若仓库保留旧摄影资源，其来源和许可文件继续随资源保留；运行界面不引用这些文件。

动态仅服务于加载反馈、短暂状态过渡和消息滚动。时长与缓动统一使用 `--motion-fast`（140ms）、`--motion-base`（220ms）、`--motion-enter`（280ms）及 `--ease-out`。主按钮有轻微按压反馈；支持鼠标悬停的设备上，提问卡片仅上移 2px，操作箭头轻移 2px。键盘焦点保留清楚的轮廓与同等操作提示。

切换提问主题时示例短暂淡入；新消息进入位移 6px，不对消息正文逐字播放；发送按钮可用、流程完成与反馈选中只做一次轻微确认。移动抽屉打开时横移 12px，遮罩淡入，不推迟焦点捕获或关闭操作。风险警示不加延迟、闪烁或装饰动画。

遵循 `prefers-reduced-motion`：关闭进入动画、悬停与按压位移及过渡，消息滚动直接定位；加载中的文字和状态仍保持可识别。不使用连续背景动画、漂浮光点、光扫或大幅缩放效果，不引入动效依赖。

## 内容与安全边界

消息、引用、反馈、账户 Cookie、SSE 和请求幂等恢复沿用既有 API 与安全边界。界面调整不得绕过来源地址白名单、会话 owner 校验、同源要求或 CSP，也不得将供应商凭据放到浏览器。

资料来自实际接口，保留发布机构、来源日期、可点击的原文和适用的 OGL 声明。点击历史回答的引用入口时展示该回答对应的资料，避免混入最新一轮来源。不能把项目改编资料标为原机构直接结论。

保留“健康信息整理与就医指引，不替代医生诊断、处方或急救服务”的说明和个人身份信息提示。界面不编造健康资讯、风险结果、资料引用、用户画像或服务在线状态。

## 验收

前端运行 `npm test` 和 `npm run build`，并验证同源 Cookie/CSP 契约。浏览器检查桌面、平板和手机，覆盖登录/注册、模板填入与编辑、消息、引用、反馈、高风险、结构化结果、移动抽屉焦点和减少动态设置。

针对三种条件分支检查节点状态：知识检索、只读结构化查询和跳过外部查询。确认被跳过的步骤不会被当作执行成功；JSON、SSE 与请求恢复的进度展示一致。检查主要文字、辅助文字、长内容换行、输入区、空状态和错误状态，修复小字号、遮挡、溢出和多余空白。

使用接口夹具做视觉验证时，明确区分夹具状态与真实模型能力。测试、构建和截图通过不等于完成真实模型联调、医学审核或生产上线验收。
